# Дашборд статистики Instagram

Сайт собирает статистику трёх Instagram-аккаунтов каждый день, хранит историю
в базе данных и показывает графики, сравнение аккаунтов, топ постов и Stories.
Можно скачать отчёт за период в PDF.

Всё бесплатно: Vercel (хостинг) + Supabase (база данных).

## Что понадобится перед началом

- Готовый токен доступа (System User token) — тот, что вы уже сгенерировали в
  Business Manager.
- Аккаунт на [github.com](https://github.com) (бесплатно).
- Аккаунт на [vercel.com](https://vercel.com) (бесплатно, можно войти через GitHub).
- Аккаунт на [supabase.com](https://supabase.com) (бесплатно, можно войти через GitHub).

## Шаг 1. База данных (Supabase)

1. Зайдите на supabase.com, нажмите **New Project**. Название — любое, пароль
   базы данных — сохраните куда-нибудь (может понадобиться позже, но обычно
   не нужен для этого проекта).
2. Дождитесь создания проекта (около минуты).
3. Слева в меню откройте **SQL Editor** → **New query**.
4. Откройте файл `supabase/schema.sql` из этого проекта, скопируйте всё
   содержимое, вставьте в редактор и нажмите **Run**.
5. Слева откройте **Project Settings** → **API**. Скопируйте:
   - **Project URL** — это будет `SUPABASE_URL`
   - **service_role key** (не anon key!) — это будет `SUPABASE_SERVICE_ROLE_KEY`

## Шаг 2. Найдите ID Instagram-аккаунтов и страниц

Для каждого из трёх аккаунтов нужен **Instagram Business Account ID** и
**ID связанной Facebook-страницы**. Проще всего узнать через Graph API
Explorer (developers.facebook.com/tools/explorer):

1. Выберите ваше приложение, вставьте токен (тот же System User token).
2. В адресной строке запроса впишите:
   ```
   me/accounts?fields=id,name,instagram_business_account
   ```
   (если вы используете System User токен, вместо `me` может понадобиться ID
   вашего Business Manager — при ошибке попробуйте вместо этого запросить
   каждую страницу напрямую: `{PAGE_ID}?fields=instagram_business_account`,
   зная ID страницы из Business Manager → Аккаунты → Страницы)
3. В ответе для каждой страницы будет `id` (это page_id) и вложенный
   `instagram_business_account.id` (это id для IG_ACCOUNTS).

## Шаг 3. Загрузите код на GitHub

1. Создайте новый репозиторий на github.com (можно приватный).
2. Загрузите туда содержимое этой папки — проще всего через веб-интерфейс
   GitHub: **Add file → Upload files**, перетащить все файлы и папки.

## Шаг 4. Разверните на Vercel

1. На vercel.com нажмите **Add New → Project**, выберите ваш репозиторий
   с GitHub.
2. Перед первым деплоем откройте **Environment Variables** и добавьте:
   - `SITE_PASSWORD` — придумайте пароль для входа на сайт
   - `CRON_SECRET` — придумайте случайную строку (например, набор букв и цифр)
   - `SUPABASE_URL` — из шага 1
   - `SUPABASE_SERVICE_ROLE_KEY` — из шага 1
   - `IG_ACCESS_TOKEN` — ваш токен из Business Manager
   - `IG_ACCOUNTS` — JSON-список аккаунтов (см. пример в `.env.example`),
     подставьте реальные id и page_id из шага 2
3. Нажмите **Deploy**.
4. После деплоя откройте файл `vercel.json` прямо на GitHub и замените
   `REPLACE_WITH_CRON_SECRET` на то же значение, что вы вписали в
   `CRON_SECRET` — закоммитьте изменение, Vercel передеплоит сайт автоматически.

## Шаг 5. Первый запуск

1. Откройте `https://ваш-сайт.vercel.app` — попросит пароль (тот, что вы
   задали в `SITE_PASSWORD`).
2. Чтобы подтянуть историю постов (лайки/комментарии за всё время), один раз
   откройте в браузере:
   ```
   https://ваш-сайт.vercel.app/api/cron/backfill?secret=ВАШ_CRON_SECRET
   ```
   Дождитесь ответа `{"ok":true, ...}` — это может занять несколько минут.
3. Чтобы сразу увидеть свежие цифры, а не ждать завтрашнего утра, откройте:
   ```
   https://ваш-сайт.vercel.app/api/cron/collect?secret=ВАШ_CRON_SECRET
   ```
4. Дальше сбор данных происходит автоматически каждый день в 6:00 (см.
   расписание в `vercel.json`, можно поменять).

## Важное ограничение (не баг)

Instagram API отдаёт **ежедневные охваты/показы/подписчиков** максимум за
примерно последние 30 дней — глубже прошлого API не хранит данные ни для
кого, это ограничение самого Instagram. Поэтому графики по этим метрикам
будут копиться только с момента первого запуска сайта. История **постов**
(лайки, комментарии) при этом подтягивается полностью — см. Шаг 5.2.

## Если что-то не работает

Самая частая причина — Meta немного меняет названия метрик в Insights API.
Если `/api/cron/collect` возвращает ошибку в поле `log` вида
`metric[0] must be one of the following values: ...` — само сообщение
подскажет актуальный список названий. Их нужно поправить в файле
`lib/instagram.ts`, в константах `METRICS_ACCOUNT` / `METRICS_STORY`.
